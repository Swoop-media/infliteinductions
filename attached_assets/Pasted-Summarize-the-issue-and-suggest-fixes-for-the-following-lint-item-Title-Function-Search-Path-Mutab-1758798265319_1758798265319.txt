Summary
The function public.upsert_learner_document does not set search_path.
Without an explicit search_path, resolution of unqualified names (tables, functions, operators) depends on the caller’s role and current search_path, which can lead to privilege escalation or calling the wrong objects.
Risks
Security: SECURITY DEFINER functions can be hijacked via objects in earlier schemas on the caller’s path.
Correctness: Unintended objects may be referenced if names are unqualified.
Fixes
Set a fixed, minimal search_path inside the function
Best practice: empty path plus explicit schema-qualification.
Update the function to include SET search_path = '' and fully qualify all referenced objects.
Example pattern: create or replace function public.upsert_learner_document(...) returns ... language plpgsql security invoker set search_path = '' as $$ declare -- variables begin -- qualify everything with schema insert into public.learner_documents(...) values (...) /* or */ perform public.some_helper(...); return ...; end; $$;

Fully qualify all identifiers
Prefix with schema for tables, views, functions, types, sequences, and operators if custom.
Example: public.learner_documents, public.some_helper, extensions.uuid_generate_v7().
If SECURITY DEFINER is required
Keep set search_path = ''.
Add a minimal, controlled path if absolutely needed (e.g., set search_path = public, pg_temp), but still fully qualify objects.
Revoke execute from anon/authenticated if the function exposes sensitive behavior, and grant explicitly to needed roles.
Validate after changes
